# PoC-01: 実行環境

- 優先: P0（M0 の対象）
- 決まること: [ADR-011](../decisions.md#adr-011-秘密情報の渡し方)、CloudWatch への送り方、配布の方法
- 関連: [MicroVMs の設計 2 章](../design/microvms.md#2-制約調査で分かった事実)、[全体設計 9 章](../design/architecture.md#9-脅威モデル)

## 目的

MicroVM の中で、何が使えて何が使えないかを確かめます。特に、実行ロールの資格情報の取り方と、秘密情報が漏れる経路を調べます。

## 前提

- [共通の安全策](README.md#共通の安全策) を満たしています。
- AWS CLI は、`lambda-microvms` のコマンドに対応した版を使います。
- 実行ロールは、STS の `GetCallerIdentity` と、ダミーの秘密情報 1 つの読み取りだけを許可します。

## 手順

1. 調査用のアプリを作ります。起動時と `/run` で、次の結果を標準出力に書きます。
   - 環境変数の名前の一覧（値は書きません）
   - IMDSv2（`169.254.169.254`）に届くか
   - コンテナ用の資格情報のエンドポイント（`169.254.170.2`）に届くか
   - AWS SDK の既定の取得順で、`GetCallerIdentity` が成功するか
   - 自分のプロセスの権限（`/proc/self/status` の `CapEff`）
2. イメージのビルドで、公開レジストリのイメージから `COPY --from` できるか確かめます（例: ghcr.io の公開イメージ）。
3. `--execution-role-arn` を付けた場合と付けない場合で起動し、資格情報の取得の結果を比べます。
4. 権限を落とした子プロセスからも、資格情報に届くかを確かめます。
5. CloudTrail のデータイベントを有効にします。`--run-hook-payload` にダミーの文字列を入れて起動し、記録に残るかを確かめます。
6. 標準出力に EMF 形式の JSON を書き、CloudWatch のメトリクスに変換されるかを確かめます。
7. 最新の aws-cdk-lib で `CfnMicrovmImage` を合成（`cdk synth`）できるかを確かめます。

## 合格条件

- 手順 1〜7 のすべてについて、「使える」「使えない」「条件つき」のどれかと、その仕組みを記録できれば合格です。
- 権限を落とした子プロセスから資格情報に届く場合は、ADR-011 の影響の欄に対策を書きます。

## 費用と後片付け

- 費用の目安: 0.5 GB の MicroVM を 2 台、各 30 分動かして約 $0.03 です。CloudTrail のデータイベントは少量です。合計で $1 未満を見込みます。
- 後片付け: [チェックリスト](README.md#後片付けチェックリスト) をすべて確かめます。CloudTrail のデータイベントの設定を必ず戻します。
