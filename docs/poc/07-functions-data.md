# PoC-07: Lambda 関数のデータ

- 優先: P1
- 決まること: モジュール B のデータ経路と、費用の計算方法
- 関連: [関数・Durable・k6 の設計 1 章](../design/functions-durable-k6.md#1-モジュール-b-lambda-関数パック)

## 目的

Lambda 関数のログから、コールドスタート・費用・OOM・タイムアウトを正しく出せるかを確かめます。

## 前提

- [共通の安全策](README.md#共通の安全策) を満たしています。
- 関数は、マネージドランタイムの ZIP 形式で、オンデマンドにします。INIT が課金対象になる条件です。
- ログの形式は JSON にします。

## 手順

1. Node.js と Python の関数を 1 つずつ用意します。
2. 次の 3 つの状況を起こします。
   - コールドスタート（設定を変えて、実行環境を作り直します）
   - OOM（割り当てたメモリを使い切ります）
   - タイムアウト（上限より長く処理します）
3. `platform.report` の項目名と値を記録します。課金時間、INIT の時間、メモリ、状態を含めます。
4. 課金時間（INIT を含む）から費用を計算し、計算式と比べます。
5. 同じログを、CloudWatch Logs と Firehose→Loki の両方に送ります。届くまでの遅れと、費用を比べます。
6. OOM とタイムアウトを、ログだけで見分けられるかを確かめます。

## 合格条件

- すべてのコールドスタートを検出できること。
- 費用の計算が、計算式と ±1% で一致すること。
- OOM とタイムアウトを、それぞれ検出できること。

## 費用と後片付け

- 費用の目安: 関数の実行、Firehose、ログの取り込みは少量で、合計 $1 未満を見込みます。
- 後片付け: 関数、Firehose のストリーム、ロググループを消します。[チェックリスト](README.md#後片付けチェックリスト) もすべて確かめます。
