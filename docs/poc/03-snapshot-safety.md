# PoC-03: スナップショットの安全性

- 優先: P0（M0 の対象）
- 決まること: [ADR-005](../decisions.md#adr-005-ビルド時は静止しrun-で起動する)、アプリ向けの SDK の設定手順
- 関連: [MicroVMs の設計 6 章](../design/microvms.md#6-静止と起動adr-005)

## 目的

同じイメージから起動した MicroVM の間で、何が重なるかを確かめます。ID・乱数・時刻・接続の 4 点を調べます。

## 前提

- [共通の安全策](README.md#共通の安全策) を満たしています。
- 送り先は Grafana Cloud の無料枠にします。

## 手順

1. 2 種類のアプリを、Node.js・Python・Rust で用意します。
   - 悪い例: ビルド時に OTel SDK を初期化します。
   - 良い例: `/run` で OTel SDK を初期化します。
2. 同じイメージから 10 台を起動します。各台で、最初の 100 個の trace ID と span ID を記録します。
3. 言語の標準の乱数（Node.js の `Math.random`、Python の `random`、Rust の `rand` の既定の乱数）の最初の値を記録します。
4. 収集器（Alloy と Rotel）をビルド時に起動した場合に、収集器が作る ID や乱数が重なるかを調べます。
5. `/run` の直後と、30 分停止して再開した直後に、時刻のずれを測ります。
6. ビルド時に開いた接続（HTTP の keep-alive、gRPC）が、起動後に使えるかを確かめます。

## 合格条件

- 良い例では、10 台の間で trace ID と span ID の重なりがゼロであること。
- 悪い例で重なるかどうかを記録できること。重なる場合は、ADR-005 の原則を必須の手順として文書にします。
- 時刻のずれが 1 秒を超える場合は、同期を待ってから返事をする設計を ADR-005 に加えます。

## 費用と後片付け

- 費用の目安: 0.5 GB の MicroVM を 10 台、各 15 分動かして約 $0.08 です。30 分の停止の間は、保存の料金だけがかかります。合計で $1 未満を見込みます。
- 後片付け: [チェックリスト](README.md#後片付けチェックリスト) をすべて確かめます。
